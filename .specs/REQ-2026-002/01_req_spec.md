# REQ-2026-002 txt2speech: 教科書テキストの音声化

状態: 草案(要求定義書の全文に基づく第 2 版)。要求定義書の章番号は「要求 3.1.2」のように引く。

## 1. 目的
教科書のテキスト(.txt / .md)を、ローカルの VOICEVOX Engine で章ごとの MP3 に変換する。外部へ送信せず、無料で、10 万文字規模を一括で、異常終了しても再開できる形で処理する。

## 2. 範囲
**含む**: テキスト入力(PDF の直接入力を含む)、前処理(ルビ、ページ表記、図表参照、英数字と単位、箇条書き、Markdown 装飾)、辞書の同期、章の分割、チャンク分割、VOICEVOX での合成(リトライ、メモリ不足時の半減再送)、ポーズ付きの結合、ラウドネスの均一化、MP3 化とタグ(カバーアートを含む)、進捗の記録と再開、設定ファイル、進捗表示、ローカル限定の保証。
**含まない(backlog.md)**: チャプターの設定、見出しの階層ごとのポーズ(小見出し 1.2 秒、章 2 秒)、形態素解析による境界判定、数字の日本語読みへの展開、図表参照符の導入文への置換、ヘッダー・フッターと章タイトルの繰り返しの除去(ページ表記と区切り線の行は除く)、全角統一、実機での性能(RTF、VRAM)の自動検証、DirectML。

## 3. 機能要件
- **[REQ-2026-002-F01] 入力**: `.txt` と `.md` を読む。文字コードは UTF-8(BOM あり・なし)を標準とし、UTF-8 として読めなければ Shift_JIS(CP932)として読む。どちらでも読めなければ、ファイル名を示して失敗する。 [要求 3.1.1]
- **[REQ-2026-002-F02] 前処理**: 次を、読み上げる文字列に変換する。(a) ルビ: 青空文庫 `漢字《かんじ》`、Markdown `[漢字](かんじ)`、`<ruby>漢字<rt>かんじ</rt></ruby>` を読みだけにする。(b) ページ表記(`--- 124 ページ ---`)と区切り線の行を除く。(c) 図表の参照符(`図1-1`、`表2-3`、`[写真]`、`※注釈`)を除く。(d) 英数字と単位記号を、読みの表で日本語の読みにする(`CO2`、`km/h`、`pH`)。3 桁区切りの数はカンマだけを除く(読みは VOICEVOX に任せる)。(e) 箇条書き(`-`、`*`、`・`、`①`)の記号を除き、項目の終わりに文末の区切り(`。`)がなければ足す。(f) Markdown の装飾記号を読み上げない。 [要求 3.1.2]
- **[REQ-2026-002-F03] 辞書の同期**: CSV(列: 表記、カタカナ読み、アクセント核位置。先頭行は見出し)で定義した専門用語を、実行の最初に VOICEVOX の `/user_dict_word` へ登録する。CSV は設定で複数指定できる。形式の誤りは、行番号を示して失敗する。 [要求 3.1.3]
- **[REQ-2026-002-F04] 章の分割**: 見出し(Markdown の `#`/`##`、`第N章`、`第N節`、`1.1` の形の数字見出し)で章に分ける。見出しがなければ全体を 1 章とする。章ごとに 1 つの MP3 を作り、ファイル名は `NN_見出し.mp3`(`NN` は 2 桁以上の連番)とする。ファイル名に使えない文字は置き換える。 [要求 3.2.1]
- **[REQ-2026-002-F05] チャンク分割**: 章の本文を、合成の 1 回分(既定は 80 文字以内)に分ける。優先順位は、段落(改行)、文末(`。` `！` `？`)、読点(`、`)、上限での強制分割。強制分割でも、同じ文字種(漢字、ひらがな、カタカナ、英数字)の連続の途中では切らない(上限の位置から手前へ戻り、文字種が変わる位置で切る。連続が上限を超える場合に限り、上限で切る)。記号のない 100 文字超の文も、この強制分割で分ける。分けた文字列を連結すると元の文字列に戻る。 [要求 3.2.2。「接続詞や助詞の前」は形態素解析が要るので、文字種による近似に置き換える]
- **[REQ-2026-002-F06] 音声合成**: VOICEVOX Engine の HTTP API で、`/audio_query` に文字列と話者 ID を渡し、得た問い合わせの話速(`speedScale`、既定 1.1。学習用に推奨される範囲は 1.05〜1.20 で、設定できる範囲は 0.5〜2.0)、音高(`pitchScale`)、抑揚、音量(`volumeScale`、1.0 固定)を設定の値にして、`/synthesis` に渡して WAV(24 kHz、16 ビット、モノラル)を得る。リクエストは 1 件ずつ順に送る。実行の最初に `/version` で疎通を確かめ、失敗したらエンジンの URL を示して、何も始めずに失敗する。一時的な失敗(接続の失敗、5xx)は、指数バックオフ(待ちを倍々に)で最大 3 回再試行する。500 が続いたときは、そのチャンクの文字列を半分に分けて再送する(メモリ不足の対処。これ以上分けられない長さになったら失敗する)。 [要求 3.3、4.2、5]
- **[REQ-2026-002-F07] 結合とポーズ**: 章ごとに、チャンクの WAV を順に 1 つに結合する。チャンクの間に、直前の区切りの種類に応じた長さの無音を入れる: 読点 200 ms、文末 450 ms、段落 900 ms、その他 100 ms(設定で変えられる)。チャンクの WAV は生成のたびにディスクに書き、結合はファイルから順に読んで行う(章全体をメモリに持たない)。 [要求 3.3.2、3.4.1]
- **[REQ-2026-002-F08] MP3 化とタグ**: 結合した音声を、FFmpeg で、-16 LUFS(±1.0)、トゥルーピーク -1.0 dBFS に正規化し(EBU R128。1 回目で測り、2 回目で測定値を使って適用する)、44.1 kHz、モノラル、128 kbps(CBR)の MP3(LAME)に変換する。ID3v2.4 のタグを付ける: Title=章の見出し、Artist=音声モデル名(既定は `VOICEVOX`)、Album=書名(既定は入力ファイルの語幹)、Track=章の連番、Genre=`Audiobook`。カバー画像(.jpg/.png)が指定されていれば、アルバムアートとして埋め込む。FFmpeg の実行ファイルは設定で指定でき、実行の最初に存在を確かめて、なければ案内を示して何も始めずに失敗する。出力先のディレクトリがなければ作る。 [要求 3.4.2、3.5、5]
- **[REQ-2026-002-F09] 再開と後始末**: 出力先に進捗のファイル(JSON)を作り、章ごとの状態と、作ったチャンクの WAV を記録する。同じ入力と設定で再実行すると、作成済みのチャンクと完了した章を飛ばして続きから行う。入力か設定が変わっていれば、進捗を捨てて最初から行う。章の MP3 が完了したら、その章の一時ファイル(チャンクの WAV、結合した WAV)を消す。全章が完了したら進捗のファイルも消す。 [要求 4.2、4.4]
- **[REQ-2026-002-F10] コマンドと設定**: `python -m src.txt2speech INPUT -o OUTDIR [--config config.yaml]` で、F01〜F09 を実行する。設定ファイル(YAML)で、話者 ID、話速、音高、ポーズの長さ、ビットレート、チャンクの上限、辞書の CSV、カバー画像、書名、音声モデル名、FFmpeg の場所、エンジンの URL を与えられる。コマンドの引数は設定ファイルより優先する。変換する章を `--chapters`(設定ファイルのキーは `chapters`)で絞れる: `N`(1 章だけ)、`A-B`、`A-`、`-B`(番号は、検出した章の通し番号で、1 から)。範囲の外の章は変換せず、出力のファイル名の番号は変わらない(`06_….mp3` は常に 6 番目の章)。範囲に章が 1 つもなければ、失敗する(終了コード 2)。表紙・目次・奥付などを飛ばす、1 章だけ試す、のに使う。進捗(処理中の章、チャンクの進み、残り時間の見込み)を標準エラーに表示し、作ったファイルの一覧を標準出力に出す。終了コードは、成功 0、入力・設定の誤り 2、エンジン・FFmpeg の失敗 3。 [要求 4.3]
- **[REQ-2026-002-F11] ローカル限定**: エンジンの URL のホストが、ループバック(`127.0.0.1`、`localhost`、`::1`)でなければ、何も送らずに失敗する(終了コード 2)。このコマンドは、ほかのホストへ通信しない。 [要求 4.4]
- **[REQ-2026-002-F12] PDF の直接入力**: 入力が `.pdf` なら、中間のテキストファイルを作らずに直接読む。しおり(アウトライン)のうち、設定した階層(既定は最上位)の項目を章とし、各項目の開始ページから、次の項目の開始ページの手前までを、その章の本文にする。最初の項目より前のページ(表紙、目次など)は読まない。章の題は、しおりの題から、単語の間に入った余分な空白を詰め、文字化けした末尾を切ったものにする。さらに、開始ページの先頭の行(ヘッダーなどを除いた後の、上から数行)と突き合わせ、先頭から一致する部分は、ページの本文の側の文字列を使う(しおりの題の中ほどに文字化けがあっても、正しい題になる)。一致する長さが短いとき(3 文字未満)は、しおりの題を使う。しおりがなければ、全体を 1 章とし、題は PDF のタイトル(なければ入力ファイルの語幹)にする。開始ページが同じ項目は、後のものを残し、本文のない章は作らない。 [利用者の要望(中間のテキストを経ない)。実データの PDF はしおりを持ち、節の見出しは本文と同じ大きさで、文字サイズでは検出できない]
- **[REQ-2026-002-F13] PDF の本文の整形**: PDF から取った行を、読み上げる文章にする。(a) 本文より著しく小さい文字の行(脚注)、数字だけの行(ページ番号)、多くのページに繰り返し現れる行(ヘッダー・フッター)を除く。(b) 行の折り返しをつないで段落にする: 字下げのある行、または行間が通常より広い行から、新しい段落を始める。見出しのように前後が広く空いた短い行は、単独の段落になる。日本語どうしの行は空白を入れずにつなぎ、英数字の語どうしは空白 1 つでつなぐ。(c) 本文中の脚注の参照記号(`注１`、`注5・6`、`注17` の形。後ろの語に続いていてもよい)を除く。ただし「注４を参照」のように文の一部として読ませるもの(後ろが `を参照`、`参照`、`を見`、`のとおり`、`の通り`)は残す。(d) 連続する空白(半角、全角)を、半角の空白 1 つにまとめる。 [実データの PDF で、脚注が 7.5 pt、参照記号が「使う注１。」の形で本文に混じっていた]

## 4. 非機能・前提
- 実機(GTX 1660 Super、VOICEVOX の GPU モード)での RTF(0.20 以下)、VRAM(4 GB 以下)、音質、1.2 倍速での聞き取りやすさは、自動テストの対象外(手動確認)。自動テストは、VOICEVOX を偽の HTTP サーバーに置き換える。
- 1 万文字の入力を、偽のエンジンで、エラーなく章ごとの MP3 にできること(受入基準の変換精度)は、自動テストで確かめる。

## 5. 未決
- 要求のポーズ表の範囲(例: 読点 150〜200 ms)から、既定を中央付近の値とした。聞いて調整する。
- 章のタイトルの繰り返しの除去、全角統一は、基準が曖昧なので backlog。
