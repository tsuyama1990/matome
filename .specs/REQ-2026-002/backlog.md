# REQ-2026-002 の積み残し(MVP に含めないもの)

| ID | 内容 | 理由 | 条件 |
|---|---|---|---|
| B-01 | MP3 のチャプター設定(要求の図 3.5) | 本文に仕様がなく、プレーヤーの対応もまちまち | 要望があったとき |
| B-02 | 見出しの階層ごとのポーズ(小見出し 1.2〜1.5 秒、章 2 秒)(要求 3.4.1) | MVP は見出しごとにファイルを分けるので、ファイル内に見出しの区切りがない | 1 ファイルに複数の節を入れる構成にするとき |
| B-03 | 形態素解析による「接続詞・助詞の前」での分割(要求 3.2.2) | 依存が増える。文字種の近似で MVP は足りる | 不自然な切れ目が実測で目立つとき |
| B-04 | 数字の日本語読みへの展開(`1000` → `せん`)、箇条書きの番号読み | VOICEVOX が読む | 誤読が目立つとき |
| B-05 | 括弧の種別ごとのポーズ(要求 3.1.2) | 文末・読点のポーズで MVP は足りる | 聞きにくいとき |
| B-06 | 図表参照符の導入文への置換(`図1-1` → `図いちの一`) | 読みの規則が未決 | 規則を決めたとき |
| B-07 | ヘッダー・フッター、章タイトルの繰り返しの除去、半角英数字の全角統一(要求 3.1.2) | 基準が曖昧 | 基準を決めたとき |
| B-08 | 実機での RTF(0.20 以下)、VRAM(4 GB 以下)、10 万文字の連続処理、音質、1.2 倍速での聞き取り(要求 4.1、受入基準) | 自動テストの対象外 | 手動確認 |
| B-09 | DirectML の対応、Windows での動作確認 | 開発環境が Linux | 必要になったとき |
| B-10 | しおりのない PDF の、レイアウトによる見出し検出(前後が広く空いた短い行、文字サイズ・太字) | MVP は、しおりのない PDF を 1 章とする。実データの PDF は、節の見出しが本文と同じ大きさだった | しおりのない PDF を実際に使うとき |
| B-11 | PDF の節の見出しでの分割(章より細かい単位) | 章単位で足りる(1 章が約 30〜40 分) | 1 章が長すぎて聞きにくいとき |
| B-12 | 脚注の本文を、章の終わりにまとめて読む | 脚注は MVP では読まない | 要望があったとき |
| B-13 | 表紙・目次・奥付などの自動判定 | `--chapters` で人が範囲を指定する。題名の語(目次、奥付など)で自動判定すると、本文を誤って飛ばすおそれがある | 範囲の指定が面倒になったとき |
