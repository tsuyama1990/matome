# REQ-2026-003 summarize: 本文の章ごとの要約(読み上げ用)

状態: 草案(第 1 版)。根拠の種類を [原典](依頼・資料)/[データ](実測)/[推論](未検証)で示す。

## 1. 目的
教科書・書籍(PDF、.txt、.md)の本文を、章ごとに LLM で要約し、txt2speech がそのまま読み上げられる Markdown にする。1 章 30 分を超える音声を、聞ける長さに縮める。[原典: 依頼「一章30分超はちと長い」「本文を要約する向けの機能」]

## 2. 範囲
**含む**: 入力と章の分割(txt2speech と共通)、章ごとの要約の生成(外部コマンド経由の LLM)、要約の密度を上げる書き直し、読み上げ向けの書式、要約の保存と再実行時の再利用、設定と実行のコマンド、外部送信の明示。
**含まない(backlog.md)**: 長すぎる章の分割要約(map-reduce)、要約の事実検査、節単位の要約、本全体の要約、読み上げ時間による長さの指定、PDF の読み取り設定の調整、LLM への API 直接接続。

## 3. 機能要件
- **[REQ-2026-003-F01] 入力と章**: 入力は `.pdf`、`.txt`、`.md`。章の分割、`--chapters`(例: `6`、`2-5`、`6-`、`-4`)の意味、PDF の読み取りは、txt2speech と同じ実装を使う(F01〜F04、F12、F13 と同じ結果)。要約するのは、選ばれた章だけである。 [原典: 同一の入力を 2 つのコマンドで使う]
- **[REQ-2026-003-F02] 要約の長さ**: 章ごとの目標の文字数を `min(本文の文字数, max(summary_min_chars, round(本文の文字数 × summary_ratio)))` とする(既定: `summary_ratio` 0.2、`summary_min_chars` 300。本文より長い要約は求めない)。この数を、プロンプトに「約 N 字」と書いて伝える。目標は目安であり、結果の長さは保証しない(検査も再試行もしない)。[データ: 第 1 章の試作は、目標 3,000 字に対し 3,754 字だった] [データ: 第 1 章(本文 10,956 字)の要約 3,754 字は、VOICEVOX 話速 1.1 で 12.7 分。約 300 字/分 → 0.2 なら約 7 分。比率の既定は聞いて調整する(未決)]
- **[REQ-2026-003-F03] 要約の生成**: 外部コマンド(`llm_command`。引数の並び)の末尾に、プロンプトを 1 つの引数として足して実行し、標準出力を結果とする。章ごとに次の順に行う。(1) 本文から要約を書かせる。(2) `density_rounds` 回、「本文と現在の要約」を渡し、「本文にあって要約にない重要な固有名詞・用語・数字・事例を 1〜3 個足し、文字数は保つ」書き直しをさせる。(3) 最後の結果を、前後の空白を除いて章の要約とする。(4) 要約の各行の行頭の連続する `#` とその後ろの空白は取り除く(txt2speech が見出しと取り違えないため)。 [原典: matome2.0 の PRD FR-1.4 Chain of Density。データ: 第 1 章で書き直しを 2 回行った結果、長さは 3,754 字のまま、本文にある語(インドネシア、ウィンドウズ、メッセンジャーアプリなど 10 語)が加わり、本文にない内容は見つからなかった。効果は小さいので、既定は 1 回とする(`density_rounds` 1)。推論: 密度が高すぎると聞き取りにくくなるおそれがある]
- **[REQ-2026-003-F04] 読み上げ向けの書式**: プロンプトは、次を条件として含む。本文に書かれた内容だけを使う/聞いて分かる話し言葉で短い文/箇条書き・記号・括弧書き・見出し記号を使わない/英語の理論名は初出で日本語の読みを添える/構成は「この章の問い、主要な内容、この章のまとめ」/出力は要約の本文のみ。 [データ: 第 1 章の試作で、この条件の出力は読み上げにそのまま使えた]
- **[REQ-2026-003-F05] 出力**: `OUTDIR/summary.md` に、選ばれた章を順に、`# 章の題`、空行、要約、空行 の形で書く(題の改行は空白に、先頭の `#` と空白は取り除く)。全章が成功したときだけ書く。失敗した実行は、既存の `summary.md` に触れない(古いファイルが残る)。標準出力にそのパスを 1 行で示す。このファイルは、`python -m src.txt2speech OUTDIR/summary.md -o ...` でそのまま読み上げられる。
- **[REQ-2026-003-F06] 再利用**: 章の要約を `OUTDIR/.summarize_work/` に、鍵つきで保存する。鍵は、1 回目のプロンプトの全文(題、本文、目標の文字数、書式の条件を含む)、書き直しの依頼文、`density_rounds`、`llm_command` から決める。鍵が同じ保存があれば、LLM を呼ばずに使う。1 つでも違えば、その章は作り直す。保存は全章の成功後も残し、古い鍵の保存は消さない(消すには `.summarize_work` を削除する)。LLM の呼び出しは時間と費用がかかるため。
- **[REQ-2026-003-F07] 失敗**: プロンプトの大きさは、`llm_command` の各引数とプロンプトを合わせた UTF-8 のバイト数で数え、`max_prompt_bytes` 以内でなければならない。実行前に、すべての選ばれた章の 1 回目のプロンプトと、書き直しのプロンプト(`density_rounds` が 1 以上のときだけ。現在の要約は目標の 2 倍と見込む)を検査し、超える章があれば、その題を示して、LLM を一度も呼ばずに失敗する(終了コード 2)。さらに、呼び出しの直前にも実際のプロンプトを検査し、超えていれば(要約が見込みより長く伸びたとき)、章の題を示して失敗する(終了コード 2)。LLM の実行で、終了コードが 0 以外、標準出力が空、標準出力が UTF-8 として読めない、`llm_timeout_seconds` を超過、のいずれかになったら、`llm_retries` 回まで再試行する(待ちは `llm_retry_wait_seconds` から倍々)。コマンドが見つからないときは、再試行せずに失敗する。失敗は、章の題を示して終了コード 3 とする。成功した章の保存は残す。タイムアウトでは、LLM のプロセスグループ全体を終了させる。 [データ: Linux は 1 つの引数を 131,072 バイトまでしか渡せない。最長の章(20,692 字)は約 62 KB で収まる]
- **[REQ-2026-003-F08] コマンドと設定**: `python -m src.summarize INPUT -o OUTDIR [--config config.yaml] [--chapters SPEC]`。設定ファイル(YAML)のキーは、`llm_command`(文字列の並び。既定は antigravity の `agy-cli`)、`summary_ratio`、`summary_min_chars`、`density_rounds`、`llm_retries`、`llm_retry_wait_seconds`、`llm_timeout_seconds`、`max_prompt_bytes`、`chapters`。コマンド行の `--chapters` が設定ファイルより優先する。章ごとの進捗(`要約 i/N: 題`)を標準エラーに 1 行ずつ出す(保存を使う章も出す)。未知のキー、範囲外の値、空の `llm_command` は、終了コード 2 で失敗する。終了コードは、成功 0、入力・設定 2、LLM の失敗 3。
- **[REQ-2026-003-F09] 外部送信の明示**: 実行の最初に、標準エラーへ「本文を `llm_command` の先頭の語 に送ります」という 1 行を出す。txt2speech(F11: ループバック以外へ通信しない)は変えない。要約は別のコマンドであり、外部送信をするのは、このコマンドだけである。 [原典: txt2speech の F11 は維持する。推論: 外部送信を 1 つのコマンドに隔離すれば、F11 の保証を壊さない]

## 4. 非機能・前提
- 実際の LLM(`agy-cli`)の品質、所要時間、要約の事実の正しさは、自動テストの対象外(手動確認)。自動テストは、LLM を偽の外部コマンド(テストが書く小さなスクリプト)に置き換える。
- 要約の質は、第 1 章の試聴で判断する(B-01 の前提)。
