# L1 全体設計: summarize

## 1. 構成
```
 INPUT(.pdf/.txt/.md) → [txt2speech.chapters: 章の読み込みと範囲選択](共通) → 章ごとに:
     prompts(目標の文字数・プロンプト) → llm(外部コマンド) → 密度を上げる書き直し × density_rounds
     → cache(OUTDIR/.summarize_work/) → OUTDIR/summary.md
 起動時: settings の検証 → 外部送信の通知 → 全章のプロンプトの大きさの確認 → 実行

 summary.md ──(別のコマンド)──> python -m src.txt2speech summary.md -o ... → 章ごとの MP3
```
`src/summarize/` に置く。txt2speech のコードを変えるのは、章の読み込みを共有できる形に出す 1 点だけ(`txt2speech/chapters.py`。今は `pipeline.py` の非公開関数にある)。
- **純粋**: 目標の文字数の計算、プロンプトの組み立て、保存の鍵、summary.md の組み立て、設定の検証。
- **境界**: `llm`(サブプロセス)、保存の読み書き(ファイル)、`cli`。

## 2. 主な判断
- **D1 別のコマンドにする**: 要約は外部の LLM に本文を送る。txt2speech の「ループバック以外へ通信しない」(REQ-2026-002 F11)を保つため、外部送信をするコマンドを分ける。出力は Markdown のファイルで、2 つのコマンドをつなぐ。 [推論]
- **D2 LLM は外部コマンドの呼び出しにする**: `llm_command` + プロンプト 1 引数。API の鍵の管理も SDK も持たない。今の利用者の環境(antigravity の Gemini)の費用を使える。別の LLM に変えるときは、設定のコマンドを変える。 [原典: 依頼「antigravity のトークンが余っている」]
- **D3 プロンプトは引数で渡す**: `agy-cli -p` は標準入力を本文として受け取らない [データ: 実測]。引数の上限(約 128 KB)は、実際の最長の章(約 62 KB)に収まる。超える章は、実行前に検出して失敗する(分割要約は backlog)。
- **D4 再利用は鍵つきのファイルにする**: 章ごとに `NN_<鍵>.txt`。進捗の JSON を持たない。鍵が違えば別の名前になるので、古い保存と混ざらない。
- **D5 密度を上げる書き直しは本文を含めて渡す**: 本文にない語を足させないため。回数は設定(`density_rounds`)。 [原典: PRD FR-1.4。推論: 回数の効果は試聴で決める]
- **D8 長さは目安にする**: 要約の長さは LLM が決める。検査と再試行は、LLM の呼び出しを増やすだけで、聞く用途では 25% の超過が害にならない [推論]。
- **D9 外部プロセスはプロセスグループで管理する**: `agy-cli` は子プロセスを起こしうる。タイムアウトで孫が残らないようにする。
- **D6 事実の検査はしない(v1)**: 試作で数字を本文と照合し、一致した [データ]。自動の検査は基準が曖昧なので backlog(B-02)。
- **D7 エラーは txt2speech の型を使う**: `InputError`(終了コード 2)、`EngineError`(外部プログラムの失敗。終了コード 3)。

## 3. 検証方針
- 偽の LLM は、テストが一時ディレクトリに書く Python スクリプト(`llm_command = [sys.executable, fake.py]`)。受け取ったプロンプトを記録し、決まった文を返す。失敗・空出力・遅延は引数や環境変数で切り替える。
- 実際の `agy-cli` の品質・時間は手動確認(第 1 章の試聴、本設計の承認前に済ませる)。
