# CYCLE 06: Pivot KJ Engine & Export Generation - UAT Plan

## Summary
The User Acceptance Testing (UAT) for Cycle 06 validates the ultimate value proposition of the `matome` platform: the ability to seamlessly transform static document content into new, multi-dimensional structures (the "Pivot KJ" feature) and export them as actionable artifacts (like PRDs or UML). This cycle proves that the system is not just a reading aid, but a powerful knowledge reconstruction engine. The UAT scenarios ensure that a user can take a processed document, select an analytical framework (an "Axis" like SWOT or System Actors), and have the AI intelligently reorganize the relevant information into that new framework while maintaining strict traceability back to the original text.

This UAT will be the final capstone in the `tutorials/UAT_AND_TUTORIAL.py` Marimo notebook. Because this feature involves complex reasoning and unstructured data extraction, the UAT will heavily rely on "Mock Mode" to guarantee the architectural plumbing—the routing of queries to the Vector DB, the formatting of complex LLM prompts, and the structured parsing of the results—functions flawlessly and predictably, regardless of the underlying AI model's performance on a given day.

## Test Scenarios

### Scenario ID: UAT-06-01
**Priority:** High
**Title:** Multi-Dimensional Knowledge Reconstruction (Pivot)
**Description:** This scenario verifies the core `PivotEngine`. It tests whether the system can take an existing `EnrichedDocument` and a user-selected axis (e.g., "Identify System Actors"), query the necessary components (Vector DB and LLM), and successfully generate a new `PivotState` data structure that categorizes the information according to the requested axis.

### Scenario ID: UAT-06-02
**Priority:** High
**Title:** Data Traceability and Schema Integrity in Pivot State
**Description:** This scenario ensures that the newly generated knowledge structure (`PivotState`) does not hallucinate sources. It verifies that every new concept or category (`PivotNode`) generated by the AI explicitly references the UUIDs of the original `SemanticChunk` objects that provided the evidence for that category, maintaining absolute data provenance.

### Scenario ID: UAT-06-03
**Priority:** Medium
**Title:** Artifact Export Generation (Markdown)
**Description:** This scenario tests the `ExportService`. It verifies that once a valid `PivotState` is generated, the system can reliably format this data into standard, readable output formats (like Markdown reports) suitable for external use (e.g., pasting into a wiki or sending to a team), completing the knowledge production workflow.

## Behavior Definitions

### UAT-06-01: Multi-Dimensional Knowledge Reconstruction (Pivot)
**GIVEN** an application configured in "Mock Mode" with a `DummyVectorDB` (pre-populated with mock chunks) and a `MockReasoningLLMService` registered in the `DIContainer`.
**AND GIVEN** the `MockReasoningLLMService` is configured to return a specific, strictly formatted JSON string representing a categorised structure when prompted for "System Actors" (e.g., `{"nodes": [{"label": "Admin User", "summary": "Manages system settings.", "source_chunk_ids": ["chunk-uuid-1"]}]}`).
**AND GIVEN** a loaded `EnrichedDocument` corresponding to those chunks.
**WHEN** the user initiates a Pivot operation requesting the "System Actors" axis via the `PivotEngine`.
**THEN** the engine must successfully orchestrate the request without throwing parsing or connection errors.
**AND** it must return a valid `PivotState` object.
**AND** the `axis_name` of the returned state must be "System Actors".
**AND** the `nodes` list within the state must contain exactly one `PivotNode` with the label "Admin User" and the expected summary, proving the system successfully translated the mock JSON output into the strict domain schema.

### UAT-06-02: Data Traceability and Schema Integrity in Pivot State
**GIVEN** a successfully generated `PivotState` object (from the previous scenario) containing a list of `PivotNode` objects.
**AND GIVEN** the original `EnrichedDocument` from which this state was derived.
**WHEN** the test iterates through every `PivotNode` in the `PivotState`.
**THEN** the `source_chunk_ids` list for every node must not be empty (unless the axis explicitly allows deductive nodes without direct sources, which is generally discouraged in this design).
**AND** for every UUID found in a node's `source_chunk_ids` list, there must exist exactly one `SemanticChunk` in the original `EnrichedDocument` with that identical UUID, proving the AI (or mock) maintained perfect traceability.
**AND WHEN** the test attempts to assign an arbitrary string to a field that should be a UUID list (e.g., `node.source_chunk_ids = "this is not a list"`).
**THEN** the Pydantic runtime must immediately raise a validation error, proving the schema strictly enforces the traceability data types.

### UAT-06-03: Artifact Export Generation (Markdown)
**GIVEN** a valid, manually constructed `PivotState` object (to isolate the test from the engine) containing multiple `PivotNode`s categorized under a specific axis (e.g., "SWOT").
**WHEN** this state object is passed to the `ExportService.generate_markdown` method.
**THEN** the method must return a non-empty string.
**AND** the returned string must contain standard Markdown formatting elements (e.g., `#`, `##`, `-`, or `*`).
**AND** the string must explicitly contain the text of the `axis_name` (e.g., "# SWOT Analysis").
**AND** the string must contain the `label` and `summary` text from every `PivotNode` present in the input state, proving the service successfully serialized the complex object into a human-readable artifact.
